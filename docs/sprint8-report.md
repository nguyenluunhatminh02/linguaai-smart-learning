## 3. OPS-01 — Docker Compose correctness: detail

**Implemented (read-only evidence).** `docker/docker-compose.yml` defines five services (postgres, redis, migrate, api, web, ai) plus volumes and a bridge network. PostgreSQL at line 3-23 uses `postgres:16-alpine`, binds to `127.0.0.1:5432`, persistent volume, health check with `pg_isready -U "$${POSTGRES_USER}" -d "$${POSTGRES_DB}"` (line 17) using env interpolation to avoid credential exposure in `docker inspect`. Redis at line 26-61 uses `redis:7-alpine`, writes ACL file to tmpfs at runtime (line 34-43), health check uses `REDISCLI_AUTH="$${REDIS_PASSWORD}" redis-cli ping` (line 55) to avoid password in argv. Migration job at line 65-84 is a one-shot service (`restart: "no"`) that runs `prisma migrate deploy` after postgres is healthy; API depends on `migrate: service_completed_successfully` (line 131). API at line 86-137 binds to `127.0.0.1:3001`, liveness health check at `/api/health` (line 120), depends on postgres/redis/migrate, memory limit 512M. Web at line 139-171 binds to `127.0.0.1:3000`, build arg `NEXT_PUBLIC_API_URL` baked at build time (line 146), runtime env `INTERNAL_API_URL` and `CMS_BACKEND_URL` for server-side routes (line 157-158), depends on api. AI at line 173-206 binds to `127.0.0.1:8000`, liveness check at `/health` (line 191), depends on redis, memory limit 256M. All services use `restart: unless-stopped` except migrate. `apps/api/src/health/health.controller.ts:27-86` implements liveness at `/api/health` (line 44) and readiness at `/api/health/ready` (line 53) with dependency checks returning 503 when dependencies are down.

**Unmeasured / risk.** Web server routes do not use `INTERNAL_API_URL`. Inspection of `apps/web/src/app/api/*/route.ts` shows: `speaking/topic/route.ts:5`, `listening/generate/route.ts:5`, `listening/upload-user/route.ts:21`, `translation/generate/route.ts:5` all read `process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3001/api/v1'`. Only `cms/upload-audio/route.ts:14` uses `process.env.CMS_BACKEND_URL || "http://localhost:3001/api/v1"`. Compose defines `INTERNAL_API_URL: ${INTERNAL_API_URL:-http://api:3001/api/v1}` at line 157 but no route reads it. This means server-side Next.js routes will fall back to `localhost:3001` in containers, which is unreachable from the web container. The roadmap at line 873 states "Web server route dùng internal backend URL (`http://api:3001/api/v1` theo cấu hình versioning thực tế); browser dùng public URL hoặc same-origin reverse proxy. Không đưa Docker hostname vào URL browser." This is not satisfied. No Docker build, `docker compose config`, startup, or readiness probe was executed for this report. The roadmap at line 880 calls for `docker compose config` smoke test but warns "tránh đăng output có secret" — no such test was run.
